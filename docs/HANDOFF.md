## 現在の状態

- 個人向けArrowNote PWAの主要画面は `index.html` に実装済み。
- 記録、日誌、グラフ、履歴、設定のタブがある。

## 今回完了したこと

- スコア、的中孔、日誌の既存保存データを利用し、日付別集計を維持した。
- 選択日基準の週間矢数・セッション数、前週比、過去28日のテーマ達成率、スコア傾向を追加した。
- 週間目標の25%、50%、75%、100%マイルストーン表示を追加した。
- 安全、負荷、出来事、スコア傾向などを優先順に判定する固定ルールコメントとルールIDを追加した。
- テスト用 `archery-log.html` とPWA版 `index.html` の両方へ同じ機能を反映した。
- Service Workerのキャッシュ名を `arrownote-pwa-v41` へ更新した。
- 振り返り8か所へ音声入力ボタンを追加した。Web Speech API未対応時はOSキーボードのマイク利用を案内する。
- 日誌へ「じっくり記録」を追加し、4種類の書き出しガイド、最大10,000文字の本文、専用下書き、本保存、再編集、削除に対応した。
- じっくり記録は `arrowNoteDeepJournalV1`、下書きは `arrowNoteDeepJournalDraftV1` に保存する。
- 設定画面へJSONバックアップの書き出し・読み込みを追加した。セッション、日誌、じっくり記録、設定を対象とし、下書きは除外する。
- 既存記録を含む保存対象へ `syncId`、`createdAt`、`updatedAt` を補完した。
- バックアップの読み込みは非破壊統合とし、同じ同期用IDでは更新日時が新しい方を採用する。
- Firebase同期の導入案を `docs/FIREBASE_SYNC_PLAN.md` に記録した。
- `firebase-sync.js` を追加し、Googleログイン、手動同期、自動同期、オフライン待機、更新日時優先、削除情報の同期を実装した。
- 設定画面へ同期状態、ログイン中アカウント、個人固定用UID、ログイン・同期・ログアウト操作を追加した。
- `firestore.rules` を追加し、初回ログインで確認した所有者UIDだけが本人のUID配下を読み書きできる最終ルールへ固定・公開した。
- Service WorkerがGoogle認証などの外部通信をキャッシュしないよう、同一オリジンのGETだけを処理するようにした。
- Firestoreがセッション内の配列内配列を拒否したため、クラウド保存時は記録本体をJSON文字列 `payload` へ包み、読込時に復元する方式へ修正した。ネスト配列を含むセッションの往復テストに合格済み。
- GitHub Pagesへ修正版が配信されていることを確認した。iPhoneが旧JavaScriptを保持したため、`firebase-sync.js?v=40` と `sw.js?v=40` を使う強制更新対策を追加した。
- iPhoneでGoogleログイン後に同期を再実行し、`Nested arrays are not supported` エラーが解消して同期成功したことを確認した。
- 練習（スコア）でターゲット9・10・X、インドア9・10、フィールド5・6を入力した際の中心的中演出を追加した。X・10・6は強いゴールド演出、9・5は軽いグリーン演出とし、試合、点を取らない練習、三つ目的の重複射では発動しない。
- スマートフォン縦画面でスクロールせず修正できるよう、現在表示中の最新的中マーカーを約0.52秒長押しして1本取り消す操作を追加した。最新矢は白い輪で強調し、見えない操作領域を広げている。
- 長押し中は赤い進行リングを表示し、指が12px相当以上動いた場合はキャンセルする。的面のコンテキストメニューは抑止し、横画面の長押し拡大とは最新矢のイベントを優先することで競合を避けた。
- 長押し削除後は5秒間「元に戻す」を表示し、復元時には点数と三つ目的の重複射ペナルティを再計算する。従来の固定取り消しボタンも予備として残した。
- エンド最終矢の入力後に長押しを開始できるよう、次エンドへの自動遷移を250msから1100msへ変更し、最新矢を押した時点で自動遷移を停止する。
- Service Workerのキャッシュ名と読込版を `arrownote-pwa-v42` / `?v=42` へ更新した。

## Goal Pace 試作（本体未統合）

- 練習（スコア）の開始前に目標点を設定し、現在点と目標点を横方向のシークバーで比較する独立テストページを追加した。
- 現在位置は緑の矢、同じ矢数での目標ペースは白線として表示する。「あと○点」は主表示にしない。
- 次エンドゲートを追加し、残り3本または6本で目標ペースを維持する合計点、回復、上積みの目安を自動計算する。
- 自己ベスト、直近の同種目、直近5回平均を切り替えるゴーストペースを追加した。現時点の比較値は表示検証用の仮データで、本体統合後は保存履歴から算出する。
- 直近最大3エンドの平均から最終得点の着地予測ゾーンを表示する。序盤は広く、残り矢数が減るほど帯を狭くする。
- 当初目標が数学的に到達困難になった場合、元の目標を消さず、狙える着地点へ分岐する `FINISH STRONG` モードを追加した。
- エンド確定時だけ短い通過演出を行い、端末の `prefers-reduced-motion` 設定にも対応した。
- アウトドア72本、30m・36本、インドア60本、フィールド72本のテストプリセットを持つ。Xは10点として計算する。
- JavaScript構文、DOM参照、通常・ゴースト・着地予測・FINISH STRONG・セッション完了の計算状態をローカルテスト済み。
- 詳細仕様は `docs/GOAL_SCORE_FEATURE.md`。本体の保存データやスコア画面は変更していない。

## カメラ撮影による着弾・スコア記録機能

- ノートPC側で検討した仕様を引き継ぐ。現時点では実装しない。
- 第1段階は、撮影した的面写真をユーザーが手動タップして着弾を登録する半自動方式とする。
- 第2段階以降で、的面検出、遠近補正、前後写真の差分、着弾候補の自動提示を検討する。
- 自動判定結果は確定せず、必ずユーザーが確認・修正して保存する。
- 写真は原則として端末内で扱い、既定では外部サービスへ送信しない。
- 保存データは既存の `arrowNoteLogsV2` の座標、点数、矢番号と互換性を保つ。
- 初期対応は40cm単的を優先し、カメラ処理は巨大な `index.html` から分離して設計する。

## 既知の注意点

- `quote-catalog.js` のメタ情報は現在 `mode: "preview"`。
- `sw.js` のキャッシュ名は `arrownote-pwa-v42`。同期モジュールとService WorkerのURLにも `?v=42` を付け、Safari/PWAの旧コード保持を回避している。
- GitHub Pagesへ反映しても、Service WorkerやSafariのキャッシュで旧画面が残る場合がある。
- 更新確認でSafariのWebサイトデータ削除やホーム画面PWAの削除を安易に行わない。`localStorage` の未同期記録を失うおそれがあるため、まず版番号更新、オンラインでの再読込、PWAの完全終了・再起動を試す。
- サービスアカウント秘密鍵、Admin SDK秘密鍵、OpenAI APIキーを `index.html` やGitHubへ追加してはいけない。Firebase Web設定値は公開クライアント識別情報として例外。
- `index.html` は単一ファイルとして大きくなっているため、将来の機能拡張前に分割を検討する余地がある。
- アプリ内ブラウザの自動操作は `file://` URLで安全ポリシーにより拒否されたため、今回の画面操作試験は手動確認待ち。HTML要素整合、JavaScript構文、集計ロジックはローカル検証する。
- 音声認識はブラウザ依存であり、`file://` テストページよりGitHub PagesのHTTPS版での実機確認を優先する。
- 現在のNotion用CSVにはじっくり記録を含めていない。
- Goal Paceは独立テストページのみで、本体のナビゲーション、Service Workerのアプリシェル、保存・同期処理にはまだ接続していない。
- Goal Paceのゴースト比較値は仮データであり、ユーザーの実記録ではない。
- JSONバックアップは、Firebase自動同期とは独立した手動退避・復元手段として残す。
- Firebase JS SDKは公式CDNのバージョン `12.16.0` を使用する。初回のクラウド機能読込にはオンライン接続が必要だが、記録画面と端末内保存は独立して動作する。
- Firebase Web設定値は公開クライアント識別情報。サービスアカウント秘密鍵、Admin SDK秘密鍵、OpenAI APIキーはGitHubへ置かない。
